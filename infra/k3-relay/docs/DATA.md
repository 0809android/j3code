# K3 Relay が保存するデータ

リレーが DB（SQLite）に書くものの、全部の一覧です。表と列は、`src/store.ts` のスキーマから自動で作っています。説明と保持期間は `scripts/generate-data-inventory.ts` に書いてあり、スキーマと食い違うと CI が失敗します。

動いているリレーの `/.well-known/k3-relay` が返す `schemaHash` は、次の値と同じになります（同じスキーマで動いていることの目安）。

`c19334243b41ddadbb46a557e256e38029d90f9bc848a3980b175f1001b7d528`

## 保存するもの

### `hosts`

登録されたホスト（K3 を動かしているマシン）の公開鍵と、日単位の日付だけ。

保持: 最後に接続した日から 365 日、接続がなければ削除（そのホストの grants、revocations、usage も一緒に消えます）。

列:

- `host_id`（TEXT、主キー）: ホストの ID。公開鍵 `Hk` のハッシュから作る（ホスト名ではありません）
- `hk`（BLOB、必須）: ホストの公開鍵（Ed25519）
- `registered_day`（INTEGER、必須）: 登録した日（1970-01-01 からの日数。時刻は持たない）
- `last_seen_day`（INTEGER、必須）: 最後に control 接続した日（日数。時刻は持たない）

### `grants`

ホストが許可した端末（ペアリング済みの端末）の公開鍵と、ホストが署名した許可証（grant）。grant に名前や権限は入れられません。

保持: 期限から 30 日、その端末が失効されてから 30 日、またはホストが削除されたとき。いちばん早いものが適用されます。

列:

- `host_id`（TEXT、主キー）: 許可したホストの ID
- `device_id`（TEXT、主キー）: 端末の ID。端末の公開鍵 `Dk` のハッシュから作る（端末名ではありません）
- `dk`（BLOB、必須）: 端末の公開鍵
- `alg`（TEXT、必須）: 端末の鍵の種類（`ed25519` または `p256`）
- `grant_json`（TEXT、必須）: ホストが署名した grant。決まった項目（版、hostId、deviceId、alg、発行と期限の時刻、nonce、署名）だけから作り直して保存する
- `issued_at`（INTEGER、必須）: grant の発行時刻（ミリ秒）
- `expires_at`（INTEGER、必須）: grant の期限（ミリ秒）

### `revocations`

ホストが署名した「この端末の許可を取り消す」記録。

保持: 30 日。

列:

- `host_id`（TEXT、主キー）: 取り消したホストの ID
- `device_id`（TEXT、主キー）: 取り消された端末の ID
- `revoked_at`（INTEGER、必須）: 取り消しの時刻（ホストが署名した値、ミリ秒）
- `sig`（TEXT、必須）: ホストの署名（検証用）
- `created_at`（INTEGER、必須）: リレーが記録した時刻（ミリ秒。保持期間の起点）

### `invites`

招待コードのハッシュ。セルフホストで `REQUIRE_INVITE=1` にしたときだけ使われ、公開リレーでは空です。

保持: 使用後、または期限後 30 日。

列:

- `code_hash`（BLOB、主キー）: 招待コードの SHA-256（コード自体は保存しない）
- `expires_at`（INTEGER、必須）: 期限（ミリ秒）
- `used_at`（INTEGER、省略可）: 使用された時刻（ミリ秒）。未使用なら空

### `usage`

ホストごとの、月ごとの中継バイト数（公平配分のための数）。通信の中身は含みません。

保持: 2 か月（62 日）。

列:

- `host_id`（TEXT、主キー）: ホストの ID
- `month`（TEXT、主キー）: 月（`YYYY-MM`）
- `bytes`（INTEGER、必須）: その月に中継した合計バイト数（両方向、1 バイトにつき 1 回）

## 保存しないもの

リレーは、次のものを DB にも、ログにも、書きません。

- **IP アドレス**: 接続元の IP は、リレーの DB にも、リレーのログにも書きません。上限の判断に使う回数は、メモリにだけ置きます。手前の Caddy のエラーログには、TLS の失敗などで接続元が出ることがあります（TRANSPARENCY.md）。
- **通信内容**: ホストと端末の間のデータは E2E で暗号化されていて、リレーは暗号文を渡すだけです。中身を解釈も保存もしません。
- **通知の中身**: 通知（P4）を足すときも、リレーは暗号文を APNs / FCM に渡すだけで、保存しません。
- **端末名**: grant には名前の欄がなく、名前の付いた grant は受け取りません。
- **ホスト名**: ホストは、公開鍵のハッシュ（hostId）としてだけ見えます。
- **プロジェクト名、スレッド名**: これらは E2E の中にだけ存在し、リレーには届きません。
- **アカウント、メールアドレス、氏名**: リレーは、人（ユーザー）と端末の対応を持ちません。

## メモリにだけ置くもの

再起動で消えます。

- nonce（認証の使い捨ての値）
- セッション
- データ接続の token
- ペアリングの窓
- IP ごとの接続や登録の回数（上限の判断のため。再起動で消えます）
- 指標（接続数、帯域、切断の理由の内訳など）

## 列名の検査

スキーマの列名に、次の語（`_` で区切った単語）を含むものがあると、テストが失敗します。`ip`、`addr`、`address`、`remote`、`name`、`label`、`nickname`、`email`、`mail`、`phone`、`user`、`username`、`account`、`hostname`、`project`、`thread`、`title`、`agent`、`ua`、`content`、`payload`、`body`、`message`。個人や接続元を特定できる列を、うっかり足さないための歯止めです。
